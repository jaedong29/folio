# 연결 자산 MVP — 2026-09-11

주식과 코인을 함께 보유한 소수 사용자가 여러 앱을 열지 않고 현재 투자자산을 확인하는 것이 목표다. 첫 화면을 `연결 자산`으로 바꾸고, 기존 장부는 `직접 기록`에서 유지한다.

## 구현 범위

| 연결 | 가져오는 항목 | 제외·제약 |
|---|---|---|
| 토스증권 | 종합매매 계좌의 국내·미국 보유 주식, 수량, 시세, 평가금액, 제공처 평가손익 | 예수금·채권 제외. 최초 연결 시 여러 계좌 중 선택하는 기능 없음 |
| 바이낸스 현물 | 현물 지갑의 사용 가능 수량 + 주문에 묶인 수량, USDT 호가 기준 평가, USDT 잔고 | 선물·마진·Earn·대출 제외. 매입 원가·실현손익 미제공. USDT 직거래 가격이 없으면 평가 불가 |

연결된 투자자산 평가금액, 주식·현물 코인·USDT 비중, 보유 자산, 마지막 성공 시각과 오류 상태를 보여준다. 토스 평가손익은 제공처의 원래 통화와 비용 차감 전 기준이다. 전체 수익률·오늘 손익으로 표시하지 않는다.

첫 조회 전이나 가격·환율 누락 시 전체 합계와 비중은 미확정으로 두고, 확인된 금액을 별도 표시한다. 빈 계좌 조회가 성공한 경우에만 0원이 된다. 조회 자체가 실패하면 이전 스냅샷을 보존하고 오래된 값임을 표시한다. 직접 기록한 자산은 이 합계에 더하지 않아 중복 집계를 막는다.

## 설정과 첫 연결

### 내 컴퓨터에서 바로 연결하기

```bash
bash scripts/run-connected-local.sh
```

[로컬 연결 화면](http://127.0.0.1:8081)에서 가입·로그인 후 바이낸스를 선택한다. 기본 개발 서버(8080)와 별도 DB를 사용하므로 처음에는 새 계정이 필요하다. 이 실행 방법은 연결 기능을 켜고 서버 암호화 키를 자동 생성한다. 계정·연결 정보와 키는 Git에서 제외한 `.folio-local`에 유지되며 재실행해도 남는다. 이 폴더는 지우거나 공유하지 않는다. 기존 8080 메모리 DB 기록은 이동시키지 않는다.

서버는 이 컴퓨터의 127.0.0.1에서만 접속 가능하며 H2 콘솔·AI·뉴스 수집은 꺼져 있다. 실제 키는 Folio의 입력창에 직접 입력한다. 계좌 연결 전에는 금융 계좌 API를 호출하지 않는다. 바이낸스에서 IP 제한을 설정할 때는 이 컴퓨터가 인터넷에 접속하는 공인 송신 IP를 사용한다.

### 배포 서버 설정

기능은 기본 비활성화다. HTTPS가 적용된 서버에 다음 환경변수를 설정한다. 로컬 개발은 localhost에서 가능하다.

```dotenv
APP_CONNECTIONS_ENABLED=true
APP_CONNECTIONS_ENCRYPTION_KEY=<Base64로 인코딩한 무작위 32바이트>
APP_CONNECTIONS_SYNC_INTERVAL_SECONDS=300
```

암호화 키는 `openssl rand -base64 32` 등으로 운영자가 생성해 서버의 비밀 환경변수로 보관한다. 저장소·채팅·로그에 붙여넣지 않는다. JWT 비밀키와 별개이며, DB 백업을 복원할 때 동일한 암호화 키가 필요하다. 현재 자동 키 교체 기능은 없으므로 키를 무작정 바꾸면 기존 연결을 복호화하지 못한다. 키와 DB 백업은 분리해 보관한다.

1. 로그인 후 `계좌 연결`을 선택한다.
2. 바이낸스는 HMAC API Key/Secret Key를 입력한다. 읽기는 허용하고 주문·출금·이체·마진·선물 등 변경 권한은 모두 끈다. 서버가 API 권한을 조회하며, 알려진 변경 권한 중 하나라도 활성화되거나 필드가 누락되면 연결을 거부한다. 서버의 고정 송신 IP만 허용하는 설정을 권장한다.
3. 토스증권은 Open API의 전용 Client ID/Client Secret을 입력하고 서버 송신 IP를 허용 목록에 등록한다. 현재 구현은 갱신마다 새 접근 토큰을 발급한다. 같은 Client ID의 이전 토큰이 무효화될 수 있으므로 다른 자동매매·조회 프로그램의 키를 재사용하지 않는다. 토스 키 자체의 조회 전용 권한 분리는 이번 검증에서 확인하지 못했다. Folio 구현은 인증 및 계좌·보유 주식 조회만 호출한다.
4. 저장 후 조회는 백그라운드에서 진행한다. 기본 주기는 완료 후 5분이며, 수동 갱신은 최근 조회 후 최소 60초 간격으로 제한한다. 화면은 10초마다 저장된 상태만 확인한다.
5. `키 변경`은 기존 조회값을 비우고 새로 연결한다. `연결 해제`는 Folio에 저장한 키와 스냅샷을 삭제한다. 제공처에서 키를 폐기하는 작업은 별도로 수행한다. 기존 DB 백업에 포함된 사본은 백업 보존 정책에 따라 만료된다.

AWS Compose에도 위 환경변수 전달을 추가했다. 현재 Compose 자체는 TLS를 종료하지 않는다. 외부 HTTP에서 연결 입력을 막는 화면 검사를 추가했지만, 서버 HTTPS와 직접 접근 차단을 대신하지 않는다. 외부 서비스에서 활성화하기 전에 HTTPS 프록시와 서버 접근 경로를 구성해야 한다.

## 저장과 처리

- `V14__account_connections.sql`: 사용자·제공처별 연결 1개, 암호화된 자격 증명, 마지막 조회 스냅샷, 작업 상태.
- AES-256-GCM의 매번 다른 nonce와 사용자·제공처 바인딩으로 자격 증명을 보호한다. 키 원문은 응답·브라우저 저장소에 반환하지 않는다. 조회 API에는 `Cache-Control: no-store`를 적용한다.
- 외부 호출은 DB 트랜잭션 밖에서 수행한다. 작업 선점과 완료 반영만 짧게 잠그며, 선점 토큰이 바뀌거나 연결이 삭제되면 늦은 응답을 폐기한다. 중단된 작업은 120초 후 재선점할 수 있다.
- 제공처 주소는 코드에 고정하고 리다이렉트를 따르지 않는다. HTTP 연결·응답 대기 시간을 제한한다. 제공처 응답 본문과 서명 URL을 오류 로그에 남기지 않는다.
- 다른 사용자의 연결은 404로 처리한다. 회원 탈퇴 시 연결도 같은 트랜잭션에서 삭제한다.
- 수동 장부의 거래 시점 환율·평단·정산·replay 구조와 연결 스냅샷은 별개다. 연결 자산은 기존 News의 `내 자산` 필터나 Evidence Agent 입력에 자동 반영되지 않는다.

| API | 동작 |
|---|---|
| `GET /api/connections` | 사용자 연결과 저장된 평가금액 조회 |
| `PUT /api/connections/{TOSS 또는 BINANCE_SPOT}` | 키 저장·교체, 202 |
| `POST /api/connections/{id}/sync` | 갱신 대기 등록, 202 |
| `DELETE /api/connections/{id}` | 연결 삭제, 204 |

## 검증 기록

- Java 테스트 246개: 암호화·소유권·작업 중복 선점·해제 후 늦은 응답·실패 시 스냅샷 유지·부분 평가·제공처 고정 응답 등을 포함. 실제 금융 API 키나 유료 모델 호출 없음.
- `node --test scripts/test-frontend.cjs`: 6개 성공. 사용자/제공처 문자열 escaping, HTTP 환경 UUID 대체, 직접 기록 진입, 로그아웃 후 늦은 토큰 갱신 차단, 실패 갱신의 잘못된 성공 알림 방지.
- 별도의 MySQL 9.3 임시 DB: V1~V14 적용 및 운영 프로필의 Hibernate 스키마 검증 성공. 운영 Compose의 MySQL 8.0 컨테이너 검증을 대체하지 않는다.
- 해당 DB를 사용하는 로컬 서버에서 HTTP 장애 모드 `PASS 49 / FAIL 0`(실시간 심볼 검증 1개 제외), 계정 생명주기 `PASS 8 / FAIL 0`.
- 브라우저: 첫 연결 안내, 가상 키 저장 후 대기, 주식·현물·USDT 합산, 원가 미확정, 금액 숨김, 직접 기록 재진입, 390px에서 문서 가로 넘침 없음. 저장된 악성 자산 이름이 텍스트로 보이며 이미지 요소 생성·스크립트 실행 없음.

로컬 화면의 잔고는 격리된 검증 DB의 가상 데이터다. 실계좌 인증·허용 IP·실제 응답·잔고 일치는 아직 검증하지 않았다. AWS 배포·외부 HTTPS·GitHub CI 실행도 이번 작업에서 수행하지 않았다.

## 실사용으로 넘어갈 조건

먼저 운영자가 자신의 계좌로 제공처별 잔고와 조회 금액을 대조한다. 이후 초대한 소수 사용자에게 열기 전에 제공처의 제3자 서비스 이용·키 보관 조건과 필요한 이용 동의를 확인해야 한다. 개인용 API가 있다는 사실만으로 다중 사용자 서비스 운영이 허용된다고 가정하지 않는다. 토스의 간편 동의 로그인 방식은 구현하지 않았다.

9월 9일 배포 점검의 MySQL 자동 재시작, 서버 밖 백업, 운영 지표 접근 제한, AI 예산 동시성 문제는 별도 미완료 항목이다. 이번 연결 기능 테스트 통과를 공개 서비스 운영 완료로 간주하지 않는다.

## 키 입력 화면 보완 (2026-09-11)

- Chart.js 4.4.1은 npm 배포 패키지의 SHA-512 무결성을 확인한 뒤 로컬 정적 파일로 포함했다. 브라우저의 CDN 접속을 제거하고 파일에 SHA-384 SRI를 적용했다. 라이선스와 원본 출처는 `static/js/vendor`에 함께 보관한다.
- 앱 문서에 CSP를 적용해 외부 스크립트·인라인 스크립트·인라인 이벤트 실행, 외부 fetch 및 폼 전송, 다른 사이트의 프레임 삽입을 제한한다. 기존 동적 차트·배분 막대에 필요한 인라인 CSS는 허용한다. Swagger/H2 문서는 이번 앱 문서 정책의 적용 대상이 아니다.
- 키 입력란은 제출 성공·실패 후와 연결 창을 닫을 때 비운다. JavaScript 실행 중 메모리까지 안전하게 덮어쓴다고 보장하지 않는다.
- 기능 테스트 후 중단할 때는 바이낸스 API Management에서 해당 키를 삭제하고, Folio에서도 연결 해제를 수행한다. 바이낸스 키 삭제가 원격 사용 권한을 폐기하며, Folio 해제는 로컬 DB의 키·잔고 삭제다. 이미 유출된 조회 정보까지 회수되지는 않는다.

이 보완은 컴퓨터 악성코드·브라우저 확장 기능·운영체제 계정 침해를 해결하지 않는다. 로컬 DB와 복호화 키는 같은 컴퓨터에 있으며, 사용자가 설정한 바이낸스 조회 전용 권한과 IP 제한도 별도로 필요하다.

보완 후 검증: Java 247개, 프런트엔드 8개 통과. 재시작한 8081 서버의 CSP 헤더와 제공되는 차트 파일의 SRI 일치를 확인했다. 브라우저에서 로컬 스크립트 경로 및 콘솔 오류 없음 확인. 실제 금융 API 키를 이용한 호출은 이번 보완에서 수행하지 않았다.
