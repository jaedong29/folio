# Folio v2 — 실제 사용과 운영을 위한 제품 정의서

> 여러 앱에 흩어진 현금·주식·암호화폐를 한 번 기록하고, 매일 30초 안에 현재 자산과 변화 이유를 확인하는 개인 포트폴리오 서비스.

## 1. v2 목표

Folio v1은 자산·거래·평단·환율·시세를 정확하게 계산하는 기술 중심 MVP였다. v2는 이 계산 기반을 유지하면서 다음 세 가지를 증명한다.

1. 사용자가 처음 들어와 막히지 않고 첫 자산을 등록할 수 있다.
2. 장애나 알 수 없는 외부 시세를 그럴듯한 숫자로 숨기지 않는다.
3. 계정과 데이터가 실제 서비스처럼 생성·변경·삭제되고, AWS에서 재시작·복구·배포를 검증할 수 있다.

## 2. 대상 사용자

### 2-1. 1차 사용자

- 여러 증권사·거래소에 자산이 흩어진 개인 사용자.
- 계좌 자동 연동보다 직접 기록과 전체 현황 확인을 우선하는 사용자.
- 주식·암호화폐·현금성 자산을 한 화면에서 원화 기준으로 확인하려는 사용자.

초기 공개 범위는 본인과 지인 3~5명으로 제한한다. 사용자 수보다 실제 데이터로 7일 이상 반복 사용되는지가 우선 성공 기준이다.

### 2-2. 제외 사용자

- Folio에서 주문·매매를 실행하려는 사용자.
- 증권사·은행·지갑을 자동 동기화하려는 사용자.
- 세금 신고나 전문 투자성과 분석을 위해 tax lot, FIFO, TWR/MWR이 필요한 사용자.

## 3. 핵심 사용자 흐름

```text
가입 → 로그인 → 첫 현금/투자자산 등록 → 거래 기록 → Dashboard 확인
  ↑                                               ↓
  └──────── 잘못 입력하면 정정·삭제·replay ────────┘
```

### 3-1. 첫 사용

- 회원가입 후 빈 화면에서 다음 행동을 안내한다.
- 사용자는 현금 또는 투자자산을 하나 등록하고, 저장 후 대시보드로 이동한다.
- 자산이 없을 때도 “첫 자산 추가” CTA를 제공한다.
- 예시 데이터는 실제 사용자 데이터와 섞이지 않는 별도 데모 흐름으로 유지한다.

### 3-2. 반복 사용

- 로그인 후 5초 안에 총자산, 오늘 손익, 보유 Position, 투자 대기자금을 확인한다.
- 모든 평가 숫자에 마지막 갱신 시각과 시세 상태를 연결한다.
- 외부 시세가 오래되거나 환율이 없으면 그 원인과 다음 조치를 표시한다.

### 3-3. 정정

- 거래 오입력은 가짜 매매를 추가하지 않고 기존 거래 삭제 후 replay한다.
- 최초 보유 수량 오입력은 별도 정정 기능으로 수정한다.
- 삭제·탈퇴처럼 복구하기 어려운 작업은 확인 문구를 요구한다.

## 4. 기능 범위

### 4-1. v2 포함

- 이메일·비밀번호 회원가입 및 로그인.
- 현재 로그인 사용자 조회.
- 비밀번호 변경.
- 비밀번호 확인을 통한 회원 탈퇴.
- 탈퇴 시 사용자의 자산·거래·Portfolio Snapshot 영구 삭제.
- 현금·은행·국내외 주식·암호화폐 수동 등록.
- 매수·매도·입금·출금 기록과 저장 전 Preview.
- 거래 삭제 후 정산·평단·실현손익 replay.
- Dashboard·Portfolio·Allocation·Asset Analysis·전체 거래 원장.
- 외부 시세·환율 조회, 마지막 성공값 폴백, stale 상태 표시.
- 빈 상태의 첫 자산 등록 CTA.
- 운영용 health endpoint.
- 운영 프로필에서 외부 secret 사용, H2 콘솔·seed 비활성화.
- 실제 사용자 시나리오와 외부 시세 장애 시나리오 자동 검증.

### 4-2. v2 후순위

- 이메일 소유권 인증.
- 비밀번호 찾기 이메일 발송.
- HttpOnly Cookie 기반 refresh token과 모든 기기 로그아웃.
- CSV 자산 가져오기·내보내기.
- 거래 수수료.
- 예약된 시세 갱신과 일일 Snapshot Scheduler.
- 가격·손익 알림.
- PWA 또는 모바일 홈 화면 설치.

### 4-3. 의도적으로 제외

- 주문 실행.
- 은행·증권사·MyData·Web3 자동 연동.
- AI 투자 조언 또는 뉴스 기반 매매 추천.
- 부동산·자동차·대출 등 종합 가계부 확장.
- 마이크로서비스·EKS·과도한 인프라 분리.

## 5. 계정 정책

### 5-1. 가입·인증

- 이메일은 소문자로 정규화하고 DB unique constraint로 중복을 최종 방어한다.
- 비밀번호는 BCrypt로 저장하고 평문을 저장하지 않는다.
- 로그인 실패 시 이메일 존재 여부를 구분하지 않는다.
- 초기 v2는 이메일·비밀번호 인증을 유지한다. 이메일 인증과 비밀번호 찾기는 메일 발송 인프라를 준비한 뒤 추가한다.

### 5-2. 탈퇴

- 현재 비밀번호와 `DELETE` 확인 문구가 모두 필요하다.
- 탈퇴는 계정, 자산, 거래, Snapshot을 한 트랜잭션에서 삭제한다.
- 삭제 완료 후 기존 JWT는 클라이언트가 제거하고 재로그인을 요구한다.
- 데이터 복구가 필요할 수 있는 운영 환경에서는 배포 전에 DB 백업 정책을 별도로 검증한다.

## 6. 신뢰성·장애 정책

### 6-1. 외부 시세 장애

```text
fresh cache → 외부 조회 → 마지막 성공 DB 값 → 알 수 없음(null)
```

- 시세 제공자 장애를 잘못된 심볼로 표시하지 않는다.
- 마지막 성공값을 사용하면 `stale`, 갱신 시각, 출처를 함께 표시한다.
- 필수 평가값을 확정할 수 없으면 `0`이나 현재 환율로 대체하지 않는다.

### 6-2. 배포·DB 장애

- 1차 EC2 스테이징에서는 MySQL Docker volume 데이터가 유지되어야 한다. 공개 운영 전에는 RDS로 분리한다.
- `/actuator/health`에서 애플리케이션과 DB 연결 상태를 확인한다.
- 배포 전후 smoke test를 수행한다.
- 실패한 배포는 이전 이미지 또는 이전 애플리케이션 버전으로 되돌릴 수 있어야 한다.
- AWS 비용 알림과 로그를 확인한 뒤 실제 사용자 공개 범위를 넓힌다.

## 7. 보안 요구사항

- 모든 자산·거래 API는 인증 사용자 기준으로 소유권을 검증한다.
- 운영 JWT secret은 환경변수로만 주입한다.
- 운영에서 H2 console, demo seed endpoint, 개발용 기본 비밀번호를 노출하지 않는다.
- HTTPS를 적용하기 전에는 실제 사용자 데이터를 받지 않는다.
- 로그에 비밀번호, JWT, 자산 금액, 거래 단가를 남기지 않는다.
- 탈퇴·거래 삭제·자산 삭제는 명시적 확인을 요구한다.

## 8. AWS 배포 기준 아키텍처

```text
Browser
  ↓
EC2: Spring Boot Docker + MySQL Docker volume (1차 스테이징)
  ↓
RDS MySQL (공개 운영 전 분리)

CloudWatch: logs / health / alarms
S3: 선택적 export·backup 보관
```

- 현재 정적 HTML·CSS·JavaScript는 Spring Boot 안에 유지한다.
- 1차 배포는 EC2 단일 인스턴스에서 앱과 MySQL을 Compose로 실행해 배포·재시작·장애 검증을 경험한다.
- 공개 운영 단계에서는 MySQL을 RDS Single-AZ로 분리하고, HTTPS·백업·알림을 추가한다.
- ECS, EKS, ALB, Redis는 실제 병목이나 사용량이 생긴 뒤 검토한다.

## 9. 검증 시나리오

### 사용자 흐름

1. 신규 가입 → 로그인 → 첫 자산 등록.
2. 현금 입금 → 주식 매수 → Dashboard 평가.
3. 거래 오입력 삭제 → 평단·잔액·실현손익 replay.
4. 비밀번호 변경 → 기존 비밀번호 실패 → 새 비밀번호 성공.
5. 탈퇴 확인 문구 오류 → 탈퇴 실패 및 데이터 유지.
6. 정상 탈퇴 → 로그인 실패 → 자산·거래·Snapshot 삭제 확인.

### 보안·장애 흐름

1. 사용자 A 토큰으로 사용자 B 자산 조회 → 접근 실패.
2. 외부 시세 비활성화 → 화면 정상 응답과 stale/unknown 표시.
3. 서버 재시작 → 계정과 데이터 유지.
4. DB 연결 실패 → health endpoint 비정상 확인.
5. 운영 프로필 → 기본 JWT secret 없이 기동 실패.
6. 최신 배포 실패 → 이전 버전으로 롤백.

## 10. 완료 기준

- 로컬 단위 테스트와 HTTP 검증이 모두 통과한다.
- 실제 배포 URL에서 가입·로그인·자산 등록·거래 입력이 동작한다.
- 외부 시세 장애를 의도적으로 재현하고 거짓 숫자가 표시되지 않는다.
- 서버 재시작 후 데이터가 유지된다.
- 다른 사용자의 자산 접근이 차단된다.
- 탈퇴 후 계정 데이터가 실제로 삭제된다.
- AWS 비용·로그·health 상태를 확인할 수 있다.
